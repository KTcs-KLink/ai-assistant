# 인사 원문 검색 확대 결과 — 2026-11-07

기존 앱의 456개 검색 조각은 임베딩이 부족해서 생긴 제한이 아니었다. 앱이 정해진 인사 규정 제목 목록과 기존 답변 허용 조건으로 **449개 조문**만 선택하고 있었다. 전체 8,511개 조각에는 인사 외 업무와 적용 범위·표 구조를 확인해야 하는 후보도 포함돼 있어, 전부를 답변 근거로 취급할 수 없다.

기존 파일과 결과를 보존한 채, 나머지 후보를 원본 파일과 대조하고 검색을 확대했다. Supabase 등 외부 DB에는 쓰지 않았다.

## 최종 연결 범위

| 용도 | 원문 구간 | 연결된 검색 조각 | 처리 |
|---|---:|---:|---|
| 답변 생성에 사용하는 인사 본문 | **528** | **536** | 기존 449개 조문에 79개 추가 |
| 추가 검토 검색 | **3,334** | **7,770** | 원문 연결 대조 통과, 답변 생성에는 사용하지 않음 |
| 개인정보 패턴으로 제외 | **8** | **205** | 검색·답변 양쪽에서 제외 |
| 합계 | **3,870** | **8,511** | 기존 검색 후보 전체의 처리 결과를 기록 |

답변용 자료는 23개 문서 파일에서 왔다. 제목 종류로 집계하면 22종이다. 원본 전체 203개 파일 중 인사 외 판정으로 검색 대상이 아니었던 6,335개 구간은 기존 상태를 유지했다.

첫 대조에서는 기존 답변 허용 표시가 있는 602개 조문·612개 조각을 확인했다. 추가로 새 문서의 본문을 살펴보니 제목만 남은 조문, 표의 다른 열이 섞인 구간, 항 번호·조문 경계가 불확실한 사례가 있었다. **신규 후보 74개는 추가 검토로 보류**했다. 처음의 602개를 최종 답변 승인 수로 사용하지 않는다. 기존 449개 기준 범위는 별도 비교 모드로 보존했다.

## 실제로 대조한 것

Codex/코드가 새 로컬 검증 기록을 만들었다. 이번 원문 감사에서는 새 GPT 분류 호출이나 문서 재임베딩을 하지 않았다.

1. 로컬 HWP/PDF/HWPX 원본 **203개**의 파일 해시와 기존 한전 출처·버전을 확인했다.
2. 정규화 TXT의 해시를 대조하고, 검색 후보 **3,870개**의 본문을 보존 원문 단위·부모 조문 범위·정규화 원문 문자 위치와 비교했다. 원문 위치가 없는 비공백 내용은 허용하지 않는다.
3. **8,511개** 검색 조각의 순서·ID·원문 부분 문자열 해시를 대조했다. 기존 `BAAI/bge-m3` 벡터의 출처 버전, 1,024차원, float32 형식, 유한값과 정규화도 확인했다.
4. 기존 인사 범위·답변 허용 조건을 유지하고, 새 자료에는 제목 외 본문 존재와 표·조문 경계·항 순서 검사를 추가했다.
5. 원문·골든셋·기존 벡터 파일은 수정하지 않았다. 새로운 인덱스에는 골든 질문·정답·평가 라벨이나 직원 정보를 넣지 않았다.

이 검사는 원본 파일 식별과 추출 문자의 연결 대조다. **원본의 모든 페이지를 새로 시각 검토한 결과나 모든 조문 의미·필수 의존관계의 완전성 승인이 아니다.** 기존 449개 자료의 과거 검토 상태도 사람 승인으로 바꾸지 않았다. 현행성·KTcs 적용·실직원 자격·독립적인 사람 승인은 미확인이다.

## 검색과 답변에서 고친 부분

- 문서명 인식 대상을 기존 고정 목록에서 실제 검증된 문서 목록으로 확장했다. 검색 결과 수를 예전 449개로 자르는 제한도 없앴다.
- 사용자가 전문 규정을 명시하면 해당 규정의 관련 본문을 우선한다. 그 문서 전체가 검토 보류 상태이면 다른 일반 규정으로 대신 답하지 않고, GPT 호출 없이 보류 이유와 검토 검색 동선을 안내한다. 단시간근로자 운영지침의 관련 본문은 현재 이 보류 범위에 있다.
- **시간제·단시간·시간선택제라는 말만으로 정규직/비정규직을 추론하지 않는다.** 근로시간 형태는 원문 조건으로 보존한다. 고용형태 필드는 코드가 명시적 표현으로 확인한 값만 모델 출력에 허용한다.
- 추가 검토 자료는 별도 검색 화면에서 이유와 함께 보여준다. 검토 검색은 원문 일부를 보여주며, 답변 생성용 근거와 섞지 않는다. 서버에서도 검토 자료의 답변 생성·인용 사용을 거절한다.
- 검토 자료 전체를 메모리에 올리던 구현은 메모리 오류가 발생해 교체했다. PC 안의 읽기 전용 FTS5 검색 파일에서 필요한 조각만 읽으며, 조회 캐시는 4 MB로 제한한다. 이 로컬 파일은 Supabase와 연결되지 않는다.

## 검증 결과와 해석

- 기존 의미 이해 검사 42개의 저장된 실제 모델 분석 결과를 재사용해, 이전 범위와 확장 범위의 검색을 비교했다. 두 범위 모두 지정 근거 누락은 없었다. 새 의미 분석 42회나 새 답변 42개를 생성한 검사가 아니다.
- 새 조문 79개를 문서명·조문 번호로 조회해 **79/79**가 상위 5개 안에 검색됐다. 첫 구현의 46/79 실패를 수정하고 재검사했다. 이는 출처로 만든 검색 연결 검사이며 독립적인 자연어 골든셋 성능이 아니다.
- 백엔드·스크립트 검사 **165개 통과**. 모델 오류, 원본·검증 기록·로컬 색인 변경, 고용형태 추론, 검토 자료의 답변 유입, 보류 문서의 일반 규정 대체, 기존 검색 수 제한을 포함한다.
- 실제 화면에서 기존 지급일 질문과 새 임원 복무규정 질문의 답변·인용을 확인했다. 단시간근로자 지침 질문은 보류 이유를 안내하고 GPT 호출 없이 멈췄다. 검토 검색 5건, 모바일 가로 넘침 없음, 브라우저 오류·외부 요청 없음, 프로필 전송 없음도 확인했다. 결과는 `browser-verification.json`에 기록했다. 실패·수정 과정은 `rejected-attempts.json`에 보존하며 성공으로 합산하지 않는다.

기존 960문항 전체의 답변 정확도를 새로 평가한 작업이 아니다. 원문 인용 일치와 자동 검사 통과도 답변 의미의 완전성이나 조직 승인을 보증하지 않는다.
