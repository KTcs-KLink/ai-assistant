## 구현 원칙

### 전체 UI/UX 시안에 적용한 추가 확인

같은 날 사용자가 전체 UI/UX를 우선 요청하여 다음 공개 자료를 추가로 확인했다. [앱인토스 현재 UI/UX 가이드](https://developers-apps-in-toss.toss.im/design/consumer-ux-guide)에서는 다음 행동을 예상할 수 있는 CTA, 쉬운 해요체, 초기 목적을 가로막는 광고·동의 팝업 방지 원칙을 확인했다. [웰로 맞춤 정책 추천](https://www.welfarehello.com/recommend-policy)에서는 공개 탐색과 맞춤 추천 진입을 확인했으며 개인 추천 결과는 로그인 전 확인 범위에 포함하지 않았다. 토스의 2021년 지원금 발표와 현재 앱인토스 UX 원칙은 별도 근거다.

이에 따라 전체 시안은 ‘홈 → 나의 혜택 → 상세 조건/근거 → AI 설명 또는 신청 준비’를 주 동선으로 하고, 규정·양식과 내 정보·동의를 상시 접근 가능한 화면으로 연결했다. 구현과 검증 범위는 [최종 UI/UX 기록](final-uiux-20261107.md)을 따른다.

- 카드에는 금액/조건/일정의 확인 수준, 판정 이유, 근거 ID·버전·본문 해시를 함께 둔다.
- 충족/확인 필요/해당 없음의 색상과 텍스트를 함께 제공한다. 모달은 기본 브라우저 dialog로 키보드 초점과 Esc 닫기를 지원한다.
- 예시 금액을 합쳐 '받을 수 있는 돈'이라고 표시하지 않는다.
- 미제공과 자녀 없음은 다른 값으로 처리한다. 미동의 값은 저장하거나 판정에 쓰지 않는다.
- 실제 신청 양식·신청 주소가 확인되지 않으면 생성 양식을 공식 양식으로 제공하지 않는다.
- 예시 카탈로그는 가상의 금액·기간·임계값이다. 한국전력 원문은 별도 참고 영역에서만 조회하고 KTcs eligibility에 적용하지 않는다.

공개 사이트 화면 캡처는 로컬 `output/playwright/benchmark-*.png`에 보관하며 재배포하지 않는다. 공개 페이지의 서비스 내용 설명과 이번 K:LINK 구현의 검증 결과는 서로 다른 근거다.
