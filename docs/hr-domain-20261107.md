기준일: 2026-11-07. 브랜치 `feat/hr-domain-priorities-20261107`. 기반은 기존 UI 커밋 `7563011`이며 main·팀원 브랜치·원본 코퍼스·기존 960 평가를 수정하지 않는다. PR은 만들지 않는다. 다른 업체를 참고한 디자인 변경은 별도 채팅·별도 clone에서 병렬 진행한다.

## 완료 기준과 현재 판단

아래 ‘개발·검사 완료’는 코드와 가상 계정/공개 참고자료에서 관찰한 기능을 말한다. 실제 KTcs 규정 적용·직원 인증·조직 승인을 대신하지 않는다. 실제 운영 완료 조건은 API `/api/benefits/hr/readiness`의 6개 gate로 별도 공개하며 현재 `production_ready=false`다.

| 순위 | 이번에 구현·검사한 내용 | 실제 회사 사용을 위해 남은 조건 |
| --- | --- | --- |
| 1 조건별 추천 | 버전 있는 규정 모델, 동의한 조건의 3상태 비교, AND 조건·구조화된 지원 제외 조건, 근속 기념일·자녀 연령·마감 비교, 설명 우선순위. 규정 SHA/원문 SHA/회사/현행성/별도 승인 기록을 모두 대조. 텍스트 예외가 판정식에 연결되지 않으면 확정 차단 | 승인된 KTcs 규정·조건/예외 번역과 해당 버전의 승인 기록. 현재 실제 승인 규정 0개 |
| 2 본인 정보·동의 | 기존 HttpOnly 세션과 본인 JWT 저장 경로 보존. 활성 직원 membership을 서버·RLS에 추가. 자가 권한 등록 차단, 요청별 회원 상태 재확인, 로그인 제한, 동의 철회 시 조건·준비·알림 삭제, 만료 세션 정리 | 정상 DB·실제 직원용 테스트 계정·조직의 회원 등록. SQL 적용과 서로 다른 사용자/익명/권한 철회 RLS 실검사 |

## 실행과 검증 화면

`start_hr.cmd`를 더블클릭하거나 저장소에서 다음을 실행한다.

```powershell
python scripts/launch_hr_domain.py
```

주소: `http://127.0.0.1:8826/hr-check`. 기존 최종 디자인 `/workspace`를 대체하는 화면이 아니라, 실제 서버 기능과 근거 연결을 확인하는 별도 작업 화면이다. ‘가상 직원으로 기능 확인’을 누른 뒤 조건 저장·추천·준비·실제 원문 질문·동의 철회를 체험할 수 있다.

서버는 기존 KTCS 루트 `.env`를 서버에서만 읽고 기존 모델 설정을 유지한다. 새 키 파일을 만들거나 키를 프론트로 복사하지 않는다. 원본 코퍼스는 읽기만 하며 서버 실행 데이터는 `.demo-logs/hr-domain/isolated-data`에 분리한다. 다른 서비스가 같은 포트를 사용하면 종료시키지 않고 실패한다. 창을 열지 않으려면 `--no-open`, 다른 포트는 `--port`를 사용한다.

로컬 디자인 대안과 연결할 때 기본 허용 Origin은 서버 주소와 `http://127.0.0.1:8824`, `http://localhost:8824`다. UI와 API는 같은 호스트 표기(권장: `127.0.0.1`)를 사용해야 Strict 쿠키가 전달된다. 다른 개발 Origin은 `KLINK_HR_ALLOWED_ORIGINS`로 명시한다. 외부 호스트에 개방하거나 운영 인증으로 간주하지 않는다.

## 프론트 연결 계약

모든 본인 정보·모델 키·Supabase JWT는 서버에서 처리한다. 브라우저는 `credentials: 'include'`와 JSON을 사용하며 API key/Authorization 헤더를 만들지 않는다. 프론트가 보낸 조건 충족 여부나 원문을 믿고 처리하지 않는다.

| 경로 | 동작 |
| --- | --- |
| `GET /api/benefits/hr/capabilities` | 세션 없는 실행기 식별. 개인 정보·키·회사 원문 없음 |
| `POST /api/benefits/session/demo` | 로컬 가상 세션. 쿠키는 HttpOnly·SameSite Strict |
| `POST /api/benefits/profile/example` | 가상 세션에만 예시 조건 로드 |
| `GET/PUT/DELETE /api/benefits/profile` | 동의한 본인 조건만 조회/저장/철회. 입력 범위 외 필드 거부 |
| `GET /api/benefits/hr/catalog` | `cards`, 3상태 `counts`, 불투명 `conditions_revision`, `configuration_required`, 회사 적용 검증 상태 |
| `GET /api/benefits/hr/evidence?q=…` | 인사 참고 원문 검색. 현재 demo만 가능. 개인정보/키 패턴·다른 업무 질문 차단 |
| `GET /api/benefits/hr/sources/{id}` | 허용된 인사 ID의 해시가 맞는 원문만 반환 |
| `POST /api/benefits/hr/answer` | `{question}`만 받음. 프로필·임의 source/승인 상태는 받지 않음. `paragraphs[].citations[]`, `sources`, `missing_information`, 검증 수준 반환 |
| `GET /api/benefits/hr/forms` | 6개 유형과 공식 파일 연결 여부. 연결 전 가짜 다운로드 없음 |
| `GET /api/benefits/hr/forms/{id}/download` | 활성 직원 + 검증된 회사 빈 양식만 허용. 경로 탈출/해시 변경/미승인 차단 |
| `GET /api/benefits/hr/preparations` | 본인 준비 목록. 변경된 조건·규정은 stale로 표시하고 체크 제거 |
| `POST /api/benefits/hr/preparations/{benefit_id}` | 최신 `{conditions_revision,policy_sha256}` 필요. 같은 혜택의 유효한 준비 중복 방지 |
| `PATCH /api/benefits/hr/preparations/{plan_id}` | `{index,checked}`. 본인 소유·유효한 준비에만 반영 |
| `DELETE /api/benefits/hr/preparations/{plan_id}` | 본인 준비 삭제 |
| `POST /api/benefits/hr/preparations/{plan_id}/submit` | 현재 409. 실제 회사에 제출되는 내용 없음 |
| `PUT /api/benefits/hr/reminders` | `{enabled}`. 외부 알림을 발송하지 않음 |
| `GET /api/benefits/hr/updates` | 동의한 경우에만 변경·마감 안내 |
| `GET /api/benefits/hr/readiness` | 6단계 실제 운영 gate와 누락 조건. 자동 검사로 조직 승인을 바꾸지 않음 |

401은 다시 로그인, 403은 허용 범위/회원 권한 부족, 409는 조건 재확인 또는 실행 미연결, 422는 입력 범위 문제, 429는 요청 한도, 503은 연결·파일 검증 문제다. 모델 제공자 오류는 원문 오류/키 조각을 노출하지 않고 고정된 `X-Klink-RAG-Failure` 코드만 전달한다. 검사를 통과하지 않은 생성 문장을 화면에 표시하지 않는다. `needs_review` 응답에서도 검증된 원문을 열어볼 수 있어야 한다. 네트워크 실패를 예시 데이터로 조용히 대체하지 않는다.

## 실제 인사 자료 범위와 모델 경계

현재 읽은 파일은 기존 `outputs/kepco_hr_full_20261102/data/reviewed_units.jsonl`이다. 전체 보존 10,205개 중 기존 자동 검색/답변 허용 602개를 확인했고, 인사 문서 제목 허용 목록과 기존 적용 범위 검사·본문 SHA 검사를 추가해 **10개 문서·449개 구간**을 새 참고 검색 범위로 삼았다. 사람 승인 구간은 0개다.

이 범위는 기존 960 contextual 평가의 248개 허용 원문, 다른 채팅의 실험 사본 1,722개 청크, 전체 인사 검색 3,870개와 서로 다르다. 원본 색인이나 모델을 교체하지 않았고 재임베딩·대규모 성능 평가를 시작하지 않았다. 새 검색 방식은 명시적으로 `hr_lexical_bm25`이며 기존 Dense/Hybrid 성능 수치를 가져다 쓰지 않는다.

GPT에는 일반 질문과 선택된 원문 구간 전체·출처 ID·버전·현행성·검토 상태·적용 대상만 전달한다. 직원 프로필·키·서버 경로는 입력에 포함하지 않는다. 실제 모델의 `responses.input_tokens.count`로 지시문·스키마·본문을 집계하고 8,192 토큰을 넘으면 필수 내용을 잘라 보내지 않고 범위를 좁히도록 안내한다. `store=False`, 출력 한도와 자동 ID/직접 인용/수치 검사를 적용한다. 조문번호는 인용한 출처의 제목·본문과 별도로 정확히 대조한다. 구조화된 응답과 인용 검사 통과는 의미 정확성·독립 사람 승인이나 실직원 자격 승인과 다르다.

## 운영 자료의 등록 조건

실제 규정/승인/양식 JSON 스키마는 `docs/hr-contracts/`에 있다. 등록 경로는 서버 전용 `KLINK_HR_POLICIES_FILE`, `KLINK_HR_APPROVALS_FILE`, `KLINK_HR_FORMS_FILE`, `KLINK_HR_FORMS_DIR`로 지정한다. 실제 자료·직원·키는 Git에 넣지 않는다. 승인 기록은 규정 ID·회사·버전·정규화된 전체 규정 digest·원문 digest·승인 참조·유효기간에 결합된다. 클라이언트의 `approved=true`로 승격할 수 없다. 금액은 승인된 규정의 표시 값이며 복잡한 인정 근속·급여/가족 조건을 지원하지 못하면 미확인으로 남겨야 한다.

`20261107020929_hr_employee_authorization.sql`은 Supabase CLI 3.0.0의 migration new로 생성한 **미적용** 스크립트다. 기존 프로필 스키마 다음에 적용하는 활성 직원 membership·본인 RLS이며 사용자 seed는 없다. 권한 있는 관리자가 직원 membership을 제공해야 한다. 일반 사용자는 membership을 생성/수정할 수 없다. 서비스 secret으로 본인 RLS 실패를 우회하지 않는다.

## 검증과 남은 외부 의존

- 서버·기존 실행기 자동 검사 **86개 통과**, TypeScript/프론트 빌드 통과.
- 실제 Chromium에서 서버 추천/조건 저장/준비/무효화/동의 철회/알림/공식 양식 미연결/6개 gate/4개 폭을 **19항목** 확인. 이 검사 자체의 유료 모델 호출은 0건이다.
- 실제 HTTP 검증에서 본문 SHA·원문 조회·모델·권한/철회·제출 차단을 확인했다. 일반 인사 질문으로 실제 GPT 연결을 수행했고, 브라우저에서 육아휴직 참고 답변·추가 확인 안내·직접 인용 펼치기를 확인했다. 초기 조문번호 검사 실패를 보완했으며 모든 실제 시도와 차단 결과는 보존했다. 성공 사례만으로 정확도를 계산하지 않는다.
- 현재 실제 KTcs 규정 승인·실사용자 RLS·정식 SSO·공식 회사 양식·실제 제출·운영 알림·복구 검증은 미완료다.
- 마지막 Supabase 확인은 공개 키 인증 성공, 데이터 API `503 PGRST002`, 대상 프로젝트 관리 접근 거절이다. 다른 연결 계정의 비활성 프로젝트를 대상으로 임의 생성·적재하지 않았다. 사용자가 기존 `.env`를 수정 중이므로 저장 완료 후 다시 연결을 검사한다. 키를 채팅에 요구하지 않는다.
- 로컬 Docker 엔진이 꺼져 있어 별도 로컬 Postgres/RLS 실검사도 수행하지 않았다. 모의 API 검사·미적용 SQL을 실제 DB/RLS 검사 완료로 표시하지 않는다.

재현 명령:

```powershell
server\.venv\Scripts\python.exe -m pytest server/tests scripts/tests -q
npm run build --prefix web
python scripts/launch_hr_domain.py --no-open
server\.venv\Scripts\python.exe scripts/verify_hr_live.py
# 아래 옵션은 실제 지정 모델 호출을 수행한다. 기본 명령은 유료 호출 없음.
server\.venv\Scripts\python.exe scripts/verify_hr_live.py --live-llm
npx --yes --package @playwright/cli playwright-cli -s=klink-hr-domain open http://127.0.0.1:8826/hr-check
npx --yes --package @playwright/cli playwright-cli -s=klink-hr-domain run-code --filename=scripts/verify_hr_browser.js
```
