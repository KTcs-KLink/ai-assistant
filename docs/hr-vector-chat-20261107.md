# 로컬 질문 임베딩 → 실제 청크 → LLM 연결

기준일: 2026-11-07. 작업 브랜치: `feat/uiux-alternative-20261107`.

AI 챗봇을 우선 연결해, 새 질문을 로컬 BGE-M3로 임베딩한 뒤 실제 문서 청크를 검색하고 지정 LLM에 근거를 전달하도록 변경했다. [연결 화면](http://127.0.0.1:8825/hr/assistant)은 기존 8825 주소를 사용한다. 이번 요청에서는 혜택 추천의 가상 규정 카탈로그는 변경하지 않았다.

## 실제 처리 경로

1. 브라우저는 `{question}`만 인사 API에 전송한다. 직원 프로필·키·JWT를 질문에 자동 첨부하지 않는다.
2. 앱 코드가 입력 범위와 개인정보/키 패턴을 검사한다. 인사 범위 밖 질문은 임베딩·LLM 호출 전에 보류한다.
3. 로컬 **BAAI/bge-m3**, revision `5617a9f61b028005a4858fdac845db406aefb181`, 1,024차원으로 질문을 매번 새로 계산한다. 질문 벡터를 기존 평가 질문에서 찾아 재생하거나 디스크에 저장하지 않는다.
4. 기존 로컬 색인의 실제 검색 창을 벡터 유사도로 정렬하고, 같은 원문 항의 중복을 합쳐 최대 5개 근거를 고른다. 검색 창의 ID·위치·본문·SHA와 해당 원문 항 전체를 결합한다. 조건·예외가 검색 창 밖에 있다는 이유로 버리지 않는다.
5. 기존 지정 LLM에 질문과 허용 원문 항을 보낸다. 초안 → 같은 모델의 원문 대조 → 코드의 인용/수치/조건 원문 검사 → 화면 표시 순서를 유지한다. 코드가 모델측 입력 토큰을 집계하며 필수 근거를 잘라 한도에 맞추지 않는다.
6. 화면에 실제 임베딩/검색 수행 여부, 검색한 청크 전체, 인용 원문과 조건·예외 원문을 표시한다. 브라우저도 청크·조건의 코드 포인트 위치와 UTF-8 SHA를 대조한다. 확인되지 않은 생성 문장은 표시하지 않는다.

질문 임베딩은 로컬 BGE가, 검색·허용 목록·무결성·전송·출력 검사는 앱 코드가, 답변 초안·원문 대조는 서버에 설정된 GPT가 담당한다. Codex가 매 질문의 서비스 호출에 들어가는 구조는 아니다. 같은 모델의 대조는 독립 사람 검증이 아니다.

## 로컬 자료와 모델 호환성

- 자료: 기존 한국전력 공개 대체자료 **10문서·449개 자동 허용 원문**, 사람 승인 0개. 회사·고용 적용 범위·버전·원본/본문 해시·현행성 미확인 상태를 보존했다. KTcs 적용은 false로 유지한다.
- 사용한 문서 벡터: KTCS 상위 작업 폴더의 `outputs/kepco_hr_full_eval_960_20261102/indexes/windows.npy`와 `windows_vectors.json`.
- 검색 창 원문: `outputs/kepco_hr_full_20261102/indexes/windows.jsonl`. 8,511개 기존 행 중 현재 허용된 인사 원문 449개에 연결된 **456개만** 검색한다. 다른 미허용 구간을 답변 범위로 확대하지 않았다.
- 사용 벡터 SHA: `36d8f936635fe9f29761691efa241cc765439e1134fcc38b71363c2c1476a98f`.
- 검색 창 SHA: `9ae1da4bf109c8f6b5c2db2ed1c563f6bc6d887f31947dff11d948b5c75ed1a0`.
- 모델 체크포인트·토크나이저·모델/차원/정규화·배열 행 순서·본문 위치·원본 파일 해시를 대조한다. 시작 시 실제 원문 창 3개를 다시 계산해 저장 벡터와 cosine ≥ 0.9999인지를 확인한다. **이 수치는 모델/색인의 수치 호환 확인이며 답변 정확도 점수가 아니다.**
- 첫 후보였던 `kepco_hr_complete_20261102`의 과거 벡터는 이름/체크포인트 표기가 같아도 현재 질문 벡터와 호환되지 않았다. 직접 창 대조에서 음의 유사도가 관찰돼 사용하지 않는다. 기존 결과 폴더의 호환 실패 기록도 확인했다. 원본을 수정해 맞추지 않고 검증된 별도 색인을 선택했다.
- 개발 중 기존 질문 벡터 1개를 진단 목적으로 수치 대조했다. 앱 코드·검색 본문·LLM 입력·질문 캐시에는 평가 질문/정답을 넣지 않았다. 960문항 평가를 새로 실행하거나 이전 점수를 새 구현의 성능으로 가져오지 않았다.

그래픽 메모리 부족을 실제로 확인해, 질문 모델은 같은 원본 가중치와 공식 XLM-R 계층을 **CPU FP32로 순서대로 읽는 방식**으로 실행한다. 문서 벡터는 기존 FP16 실행에서 저장된 FP32 벡터를 재사용한다. 표본 수치 호환 검사를 통과했으며 모든 행의 FP32 동등성을 새로 검증했다는 뜻은 아니다. 새 문서 임베딩·대규모 재임베딩·원본 파싱은 실행하지 않았다. 확인한 두 질문의 임베딩은 약 4.4~4.6초, 실제 브라우저 질문은 약 4.9초였다. 처리 시간 보장은 아니다.

## 실행과 실패 처리

`start_hr_portal.cmd`를 실행한다. 실행기는 이 체크아웃의 로컬 모델과 인사 API를 준비하고, 빈 임시 체험 세션으로 원문/수치 확인을 마친 뒤 그 세션을 종료한다. 프로필 예시 로드·LLM 호출·클라우드 상태 조회는 이 준비 단계에 없다.

| 주소 | 역할 |
| --- | --- |
| `http://127.0.0.1:8825/hr/assistant` | 연결된 AI 화면 |
| `http://127.0.0.1:8833` | 이 체크아웃의 인사 API |
| `http://127.0.0.1:8832` | 서버 전용 로컬 질문 임베딩 |
| `http://127.0.0.1:8824/workspace` | 보존한 시안 |

```powershell
python scripts/launch_hr_vector_chat.py
npm.cmd run dev:hr --prefix web
python scripts/verify_hr_vector_sources.py
```

기존 고정 Transformers 환경과 모델 캐시를 읽으며 새 모델을 다운로드하지 않는다. 실행 환경은 기본적으로 사용자 캐시의 `kepco-bge-m3-directml-20261029` Python을 재사용하되 실행 자체는 CPU다. 필요 시 서버용 `KLINK_BGE_PYTHON`으로 경로를 지정한다. 원문·벡터·고정 실행 환경이 없거나 다른 서비스가 포트를 사용하면 대체 데이터를 만들지 않고 안내한다.

질문 임베딩/색인/수치 호환 검사 실패는 LLM 생성 전에 차단한다. 연결된 dense 경로에서 키워드 검색으로 조용히 바꾸지 않는다. 과거 `launch_hr_domain.py` 실행 경로와 원문 라이브러리 검색의 lexical 동작은 호환을 위해 보존했다. 회사 승인·접근권한·SSO·공식 양식·실제 신청/결재는 기존 미확인/미연결 상태이며 클라우드 연결 재검증·적재·SQL 적용도 수행하지 않았다.

## 이번 검증과 한계

검증 JSON·화면은 [검증 자료](hr-vector-chat-20261107/README.md)에 따로 보존했다.

- 서버/스크립트 자동 검사 **115개 통과**. 새 벡터 검사 13개에는 허용 범위 교집합, 실제 행 순서, 원문 예외 보존, 변조·모델/캐시/정규화 불일치 차단, 실패 시 LLM 미호출, 실제 검색 결과만 모델에 전달하는 검사가 포함된다. 합성 TEST 자료를 썼으며 유료 호출은 없다.
- 로컬 실자료에서 호환 창 3개와 병가·휴게시간 질문 2개를 확인했다. 두 질문 모두 관련 조문이 최상위였고 범위 밖 질문은 임베딩 없이 보류됐다. 이는 제한된 연결 점검이며 검색 성능 평가가 아니다.
- 동시 준비 확인 **4건** 및 동시 질문 임베딩 **4건**이 모두 통과했다. 질문 임베딩은 모두 새 계산이었고 새 GPT 호출은 없었다.
- 실제 브라우저 질문 **1건**은 HTTP 200, 새 질문 임베딩, 실제 청크 5개, 지정 모델의 초안/원문 대조 생성 2회, 표시 답변 1문단·조건 원문 2개였다. 답변과 사용 인용을 대조해 연간 누계 증빙 기준·동일 사유 예외·증빙 미제출 처리 문구 보존을 확인했다. 회사 적용/사람 승인은 false, 직원 정보 자동 첨부·클라우드 상태 조회는 0건이다.
- 기존 UI 기능 검사 **13개/42개 화면·폭 조합**, 실제 응답 표시의 4개 폭 확인, TypeScript/프론트 빌드가 통과했다. 기존 UI 검사 중 3개의 실패/보류 상태는 명시적으로 응답을 가로챈 검사다.
- 받은 실제 응답을 재생해 청크 위치 변조·청크 SHA 변조·질문 임베딩 캐시 오표시 **3건이 브라우저에서 답변 표시 전에 차단됨**을 확인했다. 새 GPT 호출은 0회이며 실제 새 답변으로 집계하지 않는다.
- 초기 브라우저 준비 상태 실패는 질문 POST 이전에 멈춰 LLM 호출이 없었다. 해당 기록을 보존하고 CPU 경로의 호환/동시 처리 검증 후 위 실제 연결을 확인했다.

기존 `klink-demo-ui` 체크아웃과 기존 서비스는 수정·종료하지 않았다. 이 clone의 기존 시안 소스도 유지했다. `.env` 내용을 열거나 복사하지 않았으며 기존 서버가 지정 설정을 읽는다. 비밀 키·JWT·실직원 정보를 브라우저·검증 기록에 넣지 않았다.

실제 KTcs 규정 적용·현행성·독립 사람 승인과 모든 질문의 필수 조문/조건 완전성은 별도 확인 대상이다. 이번 검사는 기능 연결 검사이며 기존 검색 성능/답변 의미 평가를 대체하지 않는다.
