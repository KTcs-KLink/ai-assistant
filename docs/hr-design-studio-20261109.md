# KLINK 디자인 스튜디오와 화면 변경

기준일: 2026-11-09. 별도 브랜치 `feat/hr-design-studio-20261109`에서 직원·관리자 주요 화면에 따뜻한 페이퍼와 차분한 스톤 테마를 추가했다. 시작 기준은 `371abf54aa51e68acfe7082cc60530b70e328493`이다. 기존 네이비·블루 CSS는 보존하고 비교 모드에서 다시 사용한다. 기준 시안 8824와 이전 화면 경로도 보존한다.

[디자인 스튜디오](http://127.0.0.1:8825/hr/design)에서 직원 홈·AI·규정·문의·계정과 관리자 현황·원문·작업·비용·설정을 골라 실제 화면을 미리 본다. 편집 대상은 색상·글자 크기·제목 서체·정보 간격·모서리다. PC/모바일 미리보기, 기존 시안 비교, 크게 보기, 디자인 설정 내려받기와 브라우저별 적용을 제공한다. 기본 디자인은 페이퍼다.

현재 작업은 코드로 구현한 화면 조절이며 자유로운 캔버스 요소 배치, 드래그 편집, Figma 파일 생성·동기화를 구현한 것은 아니다. [Claude Design 공식 안내](https://support.claude.com/en/articles/14604416-get-started-with-claude-design)는 대화와 캔버스 편집을 함께 설명한다. Codex와 Figma의 연계는 [OpenAI 공식 안내](https://developers.openai.com/blog/building-frontend-uis-with-codex-and-figma)에 별도 워크플로우로 소개되어 있다. 이번에는 외부 디자인 서비스로 코드·업무 자료를 전송하지 않았다.

## 실제 동작 범위

- 미리보기는 같은 로컬 앱을 불러오며 기존 로그인·업무 권한을 사용한다. 디자인 변경 자체가 AI 질문을 전송하거나 작업을 실행하지 않는다.
- 디자인 값만 같은 출처의 부모·미리보기 화면 사이에서 전달한다. 출처와 발신 창을 대조하고 색상·숫자·선택 값을 제한한다.
- 색상은 6자리 HEX, 글자 크기는 90~120%, 모서리는 4~20px, 서체·정보 간격은 지정 값으로 제한한다. 포인트 색상에 따라 버튼 글자와 링크의 대비를 조정한다.
- 적용 버튼은 이 브라우저의 디자인 설정만 저장한다. 회사 공통 설정·서버 권한·직원 프로필·규정 적용 상태를 바꾸지 않는다. 저장이 차단되면 실패를 표시한다.
- 설정 다운로드는 디자인 값만 포함하며 직원·문의·대화·키를 포함하지 않는다. 기존 디자인도 선택·적용할 수 있다.
- 이전 화면과 와이어프레임은 기본적으로 보존된 테마를 사용한다. 복지 추천을 다시 표시하지 않는다.

## 확인 결과와 남은 검사

TypeScript 포함 프론트 빌드를 통과했다. 화면에서 포인트 색상과 글자 크기를 바꿨을 때 미리보기 값이 변경되고 작성 중인 질문이 유지되는 것을 확인했다. 기존 시안 비교에서 보존된 테마로 전환하는 것도 확인했다. 스타일 검사에서는 질문을 전송하지 않았다.

역할·자동화 종류를 바꾸는 별도의 자동화 화면 구성안에서 직원과 서비스 운영자 전환을 확인했다. 이 화면은 설계안이며 새 규정 승인·색인 반영·외부 알림을 실행하지 않는다. 구조·스크립트 문법·외부 API 호출 없음도 검사했다.

추가 브라우저 검사 도중 연결 시간 초과가 발생해 화면 이동 뒤 조절 유지, 적용 후 재접속, 모바일 배치의 전체 확인은 마치지 못했다. 해당 항목은 통과로 기록하지 않는다. 이번 디자인 변경에서 검색 성능 평가·답변 의미 평가·사람 승인·새 임베딩을 수행하지 않았다. 기존 운영 검사 24개를 이번 디자인 변경의 새 검사로 합산하지 않는다.

새 자동화의 화면·벤치마킹은 [글로벌 조사](global-hr-automation-benchmark-20261109.md), 기능 우선순위는 [SaaS 추가 기능](hr-saas-feature-backlog-20261109.md)에 정리했다. 회사 SSO·실제 신청/결재·KTcs 적용·서비스 색인 교체·Supabase 적재의 연결 경계는 유지한다.
