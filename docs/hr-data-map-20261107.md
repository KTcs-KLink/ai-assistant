## 청킹 방식

1. 장을 부모로 보존한다. 확인된 절이 있으면 자식으로 삼고, 절이 없으면 조 단위로 내려간다.
2. 그 안에서 완전한 조문을 원문 단위로 보존한다. 현재 449개 조문 중 131개는 절 아래에서, 318개는 조 단위 대체 경로에서 나온 단위다.
3. 임베딩 검색에만 문서명·제목 경로와 원문 구간을 붙인 최대 700 BGE 토큰의 검색 구간을 사용한다. 연속 구간은 최대 150문자, 짧은 구간은 길이의 1/4까지 겹친다.
4. 원문 위치와 해시를 유지한다. 검색 구간이 찾힌 뒤에는 허용 조문 원문을 답변 근거로 사용하며, 필요한 조건·예외를 700토큰에 맞추어 버리지 않는다.

## 임베딩과 저장 위치

- 모델: `BAAI/bge-m3`, 1,024차원, L2 정규화, 저장 배열 `float32`.
- 실제 문서 벡터: KTCS 작업 폴더의 `outputs/kepco_hr_full_eval_960_20261102/indexes/windows.npy`.
- 검색 구간·원문 위치: `outputs/kepco_hr_full_20261102/indexes/windows.jsonl`.
- 골든 질문: `outputs/kepco_hr_gold_960_20261102/data/golden_set.jsonl`.
- 로컬 NumPy 파일을 사용한다. 이번 작업에서 문서 8,511개를 다시 임베딩하지 않았고, Supabase 적재는 사용자 요청으로 보류한다.
- 새 실제 질문은 동일 모델로 로컬에서 임베딩한다. 골든 질문의 기존 벡터는 오프라인 비교에만 사용하며 서비스의 질문 검색에 사용하지 않는다.

`python scripts/inspect_hr_data_map.py`는 원문·질문·벡터를 변경하지 않고 재확인 결과를 KTCS의 `outputs/klink_hr_quality_closeout_20261107/data-inventory.json`에 남긴다.

한전 공개 대체자료이며 KTcs 내부 사규가 아니다. 현재 사람 승인된 조문은 0개이며, 이 골든셋도 독립적으로 사람 승인을 받은 정답집이 아니다.
