## 이번 작업에서 확인한 기존 자산

- `ai-assistant`: React/Vite 프론트, FastAPI PDF 검색·SSE, 로그인, 출처, 관리자 진단. 최신 원격 작업 브랜치를 새 브랜치에서만 fast-forward로 받아 기존 변경을 보존했다.
- `knowledge-mcp`: main `9bf12bb`, PDF 증분 적재 브랜치 `70d1916`. `src/mcp`에는 실제 MCP 서비스 구현이 없고, 공개 원문 18개 manifest의 재배포 상태는 `unknown`. README의 초기 계획과 실제 브랜치 구현을 구분했다. 이 저장소는 수정하지 않았다.
- 로컬 전체 인사 자료: 보존 단위 10,205개 / 검색 범위 3,870개 / 자동 답변 허용 602개 / 사람 승인 0개를 현재 JSONL에서 다시 집계했다. 기존 960 평가 결과와 다른 범위다. 원문·색인·평가를 수정하거나 새 임베딩을 만들지 않았다.
- 루트 `.env`: 기존 GPT 모델 설정 존재. 키 값은 출력·복사·Git 저장하지 않는다. 기존 서버는 `KLINK_ENV_FILE`을 명시할 때 이 파일을 읽으며 `OPENAI_MODEL`을 존중한다.
- Supabase 재점검: 공개 키 인증 200 / 의도적으로 잘못된 대조 키 401로 공개 키 유효성을 확인했다. REST 루트 401만으로 공개 키가 잘못됐다고 안내했던 판단을 정정했다. 데이터 API 0행 조회는 503 `PGRST002`, 비밀 키는 Invalid API key 401. 대상 프로젝트의 관리 접근은 권한 거절. 별도 계정의 비활성 프로젝트와 혼동하지 않는다.

## 역할과 증거 경계

Codex는 구현·실행·출처 무결성·UI 검사를 수행한다. 서비스의 코드는 조건 비교·근속 계산·동의·세션·출처 해시·회사 범위 검사에 사용한다. GPT는 직원 조건을 받지 않으며 eligibility를 결정하지 않는다. 클릭한 가상 규정만으로 설명 초안을 만들며 인용 검사를 통과해도 사람 승인으로 보지 않는다. 이번 가상 규정 판정 테스트는 실제 KTcs 자격 정확도 평가가 아니다. 원문 조회는 키워드 참고 조회이며 기존 BM25/Dense/Hybrid 성능 재평가가 아니다.

실제 KTcs 현행 규정, 구조화된 필수 조건·예외, 회사 양식과 권한 계약이 없는 한 실직원의 자격·금액·마감을 확정하지 않는다. Supabase 키만으로 조직의 HR 사용 승인이나 회사 규정의 승인까지 충족되는 것은 아니다.
