# 실무형 AI 업무 도우미

기준일: 2026-11-07. 브랜치: `feat/hr-saas-assistant-20261107`. 시작 커밋: `cd456ca5d7e10edd355119cfaf462ad124be3402`.

`http://127.0.0.1:8825/hr/assistant`의 대화 화면을 다시 구성했다. 질문·답변을 중심에 두고 입력창을 하단에 유지한다. 근거 자료는 PC에서 별도 패널로, 작은 화면에서는 대화상자로 열어 확인한다. 이전 화면은 `/hr/assistant-previous`에 원래 공통 화면과 함께 보존했다.

## 작업 흐름

- 질문 예시는 작성창에만 반영한다. 사용자가 전송하기 전에는 답변 요청을 보내지 않는다. 홈·전역 검색에서 넘긴 질문도 같은 방식으로 이어쓴다.
- 답변은 이해한 질문, 참고/검토 상태, 본문과 인용 번호를 구분한다. 인용을 누르면 현재 원문을 다시 조회하고 ID·버전·본문 SHA를 대조한 뒤 표시한다.
- 원문 검색 탭에서 한전 자료를 직접 검색할 수 있다. 검색 결과도 회사·적용 범위·본문 SHA를 확인한다. 질문의 답변 근거와 별도로 검색한 자료를 탭과 문맥으로 구분한다.
- 답변 복사는 본문, 조건·예외 원문, 추가 확인 항목, 인용 출처·버전과 적용 한계를 함께 포함한다. 클립보드 권한 오류는 화면에 알린다.
- 현재 대화의 질문 목록에서 해당 질문으로 이동할 수 있다. 대화는 현재 화면의 메모리에만 유지하며, 서버 대화 이력이나 영구 저장을 구현한 것으로 표시하지 않는다.
- 대기 중 경과 시간은 화면이 잰 실제 대기 시간이다. 서버가 반환하지 않는 임베딩/생성 단계 완료나 예상 완료 시간을 만들지 않는다. 수신 중지는 브라우저 요청을 중단하며 이미 시작한 서버 처리는 계속될 수 있다.

## 유지한 연결과 경계

질문은 기존 `/api/benefits/hr/answer`로 `{question}`만 보낸다. 500자 한도, 540초 응답 대기, 세션 쿠키, 서버의 지정 모델, 실제 검색 경로를 유지했다. 기존 `checkedAnswer`와 인용·수치·원문 위치·해시 검사 코드는 변경하지 않았다.

질문 확인, 전체 보류, 일부 답변, 조건 범위 검토와 적용 미확인은 서로 구분한다. 조건·예외 원문 전체와 조회 원문 전체를 펼쳐 확인할 수 있다. 검색 점수나 조문 수를 답변 정확도 또는 사람 승인으로 바꾸지 않는다. 원문 불일치·알 수 없는 출처·전송 오류에 예시 답변을 대신 표시하지 않는다.

8844 API와 8841 인코더는 원래 인사 개발 채팅이 관리하는 기존 서비스를 사용한다. 백엔드, 원문·벡터 색인, 기존 시안과 업무 홈, Supabase 설정은 수정하지 않았다. Supabase 연결 재검증·적재·SQL 적용도 HOLD로 유지한다. KTcs 적용·현행성·조직 최종 승인과 실제 직원 인증은 별도 연결/확인 대상이다.

[검증 자료](hr-saas-assistant-20261107/verification.json), [실제 답변 PC](hr-saas-assistant-20261107/live-1440.png), [실제 답변 모바일](hr-saas-assistant-20261107/live-390.png), [모바일 원문 확인](hr-saas-assistant-20261107/source-390.png), [새 대화 PC](hr-saas-assistant-20261107/empty-1440.png), [새 대화 모바일](hr-saas-assistant-20261107/empty-390.png)을 보존했다.

- 실제 새 질문 1건을 전송했다. HTTP 200, 답변 2문단·조회 원문 5개를 확인했다. 응답에 기록된 모델 생성은 질문 이해/초안/원문 대조의 총 3회였다. 실제 본문과 인용, 현재 원문 열기를 확인했다. 실제 응답을 1440/768/390/360px에서도 검사했다.
- 최신 실제 응답을 재생한 검사와 합성/변조 검사 11개가 통과했다. 실제 원문 GET 검색·조회, 질문 목록, 조건까지 포함한 복사 내용, 확인 질문, 전체/부분 보류, 원문 SHA·인용·질문 조건 변조, 503 복구, 여섯 화면 폭과 이전 화면 접근을 구분했다. 클립보드는 검사 브라우저에서 명시적으로 대체했으며 사용자 클립보드를 덮어쓰지 않았다.
- 지연된 합성 503 응답 1건으로 수신 중지 후 늦은 결과가 표시되지 않고 새 대화로 초기화되는 것을 확인했다. 이 검사는 서버 모델 취소 확인이 아니다.
- TypeScript를 포함한 프론트 빌드가 통과했다. 브라우저 스크립트 오류, 직원 필드 자동 첨부, 브라우저 Authorization 헤더와 클라우드 설정 조회는 없었다.

이 결과는 화면·전송·출처 연결 검사다. 전체 검색 성능이나 답변 의미 평가, 독립 사람 승인 또는 고객사 운영 준비 완료를 뜻하지 않는다. Codex는 화면과 검사를 구현했고, 기존 앱 코드는 검색·검증을, 지정 GPT는 실제 질문의 이해·답변·같은 모델의 원문 대조를 수행했다.

## 재현

`npm.cmd run build --prefix web`로 빌드한다. 보존된 실제 실행 결과가 있는 환경에서는 `python -B -X utf8 scripts/prepare_hr_saas_assistant_replay.py --latest-live`로 재생 파일을 준비한 뒤 Playwright CLI에서 `output/playwright/verify_hr_saas_assistant.generated.js`를 실행한다. 새 모델 호출은 없다.

`scripts/verify_hr_saas_assistant_live.js`는 실제 새 질문을 전송하므로 모델 생성이 발생한다. `scripts/verify_hr_saas_assistant_cancel.js`는 합성 지연 응답만 사용한다. 원본 응답과 재생용 원문 복사본은 무시되는 `output/playwright`에 두고, 검증 자료에는 키·직원 쿠키·전체 원문 JSON을 저장하지 않는다.
