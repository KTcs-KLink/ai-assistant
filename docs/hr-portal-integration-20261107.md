# K:LINK 대안 시안의 인사 기능 연결

기준일: 2026-11-07. 작업 브랜치: `feat/uiux-alternative-20261107`.

> 후속 변경: 최신 답변 경로는 8828이며 조건·예외 원문을 바로 표시한다. 클라우드 저장소 자동 점검은 중단했다. 아래는 최초 연결 당시 기록으로 보존하며, 현재 실행/검증은 [조건·예외 표시 후속 기록](hr-condition-ui-20261107.md)을 따른다.

새 기업용 포털 디자인에 원래 채팅의 인사 BFF를 연결했다. 디자인 예시와 서버 연결 화면은 주소·데이터·상태를 분리했다.

| 화면 | 주소 | 데이터와 동작 |
| --- | --- | --- |
| 보존된 대안 디자인 시안 | `http://127.0.0.1:8824/workspace` | 기존 가상 규정·고정 예시 응답·메모리 상태. 서버 API 호출 없음 |
| 인사 기능 연결 화면 | `http://127.0.0.1:8825/hr` | 실제 BFF 접속·조건 저장·추천·준비·원문·질문·변경 안내 |
| 원래 백엔드의 기능 점검 화면 | `http://127.0.0.1:8826/hr-check` | 원래 채팅이 개발한 서버 확인 화면. 덮어쓰지 않음 |

기존 `klink-demo-ui` 체크아웃과 8822 서비스는 수정·종료하지 않았다. 이 clone의 기존 `web/src/portal`, `web/src/workspace`, 기본 `web/vite.config.ts`도 `a23dad3`와 동일하다. 기존 화면의 서버 미호출과 예시 안내를 브라우저에서 다시 확인했다. 이전 [시안 문서](uiux-alternative-20261107.md)는 해당 예시 화면의 기록으로 보존한다.

## 연결한 기능과 적용 전인 부분

| 항목 | 지금 연결한 내용 | 화면에 별도로 표시하는 한계 |
| --- | --- | --- |
| 접속 | 사용자가 명시적으로 시작하는 서버의 예시 직원 접속, HttpOnly 세션, 접속 종료 | 가상 직원. 회사 계정·정식 SSO 미연결. 실제 비밀번호 입력 화면 없음 |
| 조건·동의 | 동의한 고용형태·입사일·자녀 나이·가구원 수를 서버에 조회/저장/철회 | 직접 제공한 조건이며 인가된 HR 원장이 아님. 현재 체험은 가상 조건만 사용 |
| 혜택 | `/hr/catalog`의 상태·이유·조건·예외·출처·기한 표시 | 가상 규정의 예시 금액·일수. 실제 KTcs 현행 규정 승인 0건. 지급 자격 확정 아님 |
| 준비 | 규정 SHA·조건 revision을 함께 전송해 서버 준비 목록 생성, 체크·삭제·새로고침 조회 | 변경된 조건/규정의 체크 무효화. 실제 제출·승인은 연결 전이며 버튼 비활성화 |
| 참고 원문 | 실제 인사 참고 원문 검색과 ID별 최신 원문 조회. 검색 시점과 조회 시점의 버전·SHA도 비교 | 한국전력 10문서·449구간. 사람 승인 0건. KTcs 적용·현행성 별도 확인 |
| 질문 | 일반 질문만 BFF에 전송. 기존 서버의 지정 모델과 근거 검사를 사용하고 인용·원문 표시 | 프로필을 자동 첨부하지 않고 입력한 질문만 전달. 생성 문장 보류를 처리하며 의미 정확성/독립 승인 보증 아님 |
| 공식 양식 | BFF의 6개 양식 안내와 공식 파일·버전·다운로드 권한 상태 표시 | 공식 회사 파일 0개. 임의 양식 생성·가짜 다운로드 없음 |
| 변경·마감 | 서버에서 화면 내부 안내 동의를 저장하고 현재 변경/마감 응답 표시 | 예시 규정 일정. 메일·문자·회사 알림 발송이나 운영 알림 연결 아님 |
| 준비 상태 | 서버의 6개 readiness gate, 회사 승인 규정·양식 수·원문 범위·직원 저장소 상태 표시 | 실제 DB/RLS·SSO·회사 신청/결재·조직 운영 승인 미검증 |

직원 저장소의 마지막 공개 상태는 `database_unavailable / PGRST002`다. UI는 이 오류를 계정 연결 완료로 표시하지 않는다. 변경 가능한 상태는 서버에서 다시 조회하며, 정식 SSO를 단순한 인증/DB 응답으로 자동 승격하지 않는다.

## 구현과 통신 경계

원래 채팅이 푸시한 인사 브랜치 `0c9ab56e22ef85fa3dda4db5e96814baa029b101`을 이 clone에 병합했다(병합 커밋 `ce5db3d`). 인사 백엔드·마이그레이션 파일은 그 브랜치 그대로이며, UI 연결 작업에서 서버 로직을 별도로 고치거나 SQL을 적용하지 않았다. [원래 API 계약](hr-domain-20261107.md)과 [등록 스키마](hr-contracts/)를 함께 보존했다.

- 새 UI는 `web/src/hr/`에 있다. 기존 디자인의 시각 요소를 재사용하고, 가상 WorkspaceProvider 대신 별도의 서버용 HrProvider를 사용한다. 회사 근거 화면에 기존 가상 Source 컴포넌트를 쓰지 않는다.
- `web/src/App.tsx`에 `/hr/*` 지연 로딩 경로를 추가했다. `/workspace/*`의 기존 구현은 바꾸지 않았다.
- `web/vite.hr.config.ts`는 8825만 사용하고 `/api/benefits`만 8826 BFF로 전달한다. 기존 8824 설정은 그대로다. 프론트 요청은 `credentials: 'include'`를 사용한다.
- 개발 프록시는 서버로 전달하는 Origin을 해당 BFF의 자체 주소로 설정해 기존 서버의 요청 출처 검사와 함께 동작한다. 임의 API 경로나 외부 호스트에 대한 범용 프록시가 아니다. 브라우저에는 JWT·GPT/Supabase key·Authorization 헤더를 만들지 않는다.
- `.env` 내용은 열거나 복사하지 않았다. 기존 서버가 서버 전용 설정을 사용한다. 프론트 빌드에 키를 넣지 않았다.
- 현재 프록시는 로컬 개발 실행용이다. 외부 배포와 운영의 동일 출처 BFF 라우팅은 별도 작업이며 완료로 표시하지 않는다.
- 네트워크/조회 실패 시 가상 추천이나 답변으로 대체하지 않는다. 접속 만료 시 개인 화면을 숨기고 다시 시작하도록 안내한다. 조건·규정 충돌 시 최신 서버 목록을 다시 조회한다.
- 준비·동의·삭제는 서버 응답을 확인한 뒤 성공으로 표시한다. 접속의 서버 메모리 상태는 서버 재시작·만료 이후까지 보관된다고 주장하지 않는다.
- 질문 응답의 허용된 인용·원문 일치를 한 번 더 확인한다. `generated_text_withheld`이면 생성 문장은 표시하지 않고 원문/추가 확인 항목만 표시한다. 검사 통과를 의미 승인으로 바꾸지 않는다.

## 실행

`start_hr_portal.cmd`를 실행한다. 먼저 기존 8826 인사 서비스를 확인하며, 없으면 병합된 원래 실행기로 **이 clone의** 서버를 시작한다. 이미 정상 실행 중인 서비스는 재시작하지 않는다. 원래 체크아웃이나 8822/8824 서비스를 변경하지 않는다.

수동으로 실행할 때는 다음 순서다.

```powershell
python scripts/launch_hr_domain.py --no-open
npm.cmd run dev:hr --prefix web
```

API 서버를 새로 시작하려면 Python 의존성이 필요하다. 기존 서버가 실행 중이면 이를 그대로 재사용한다. 실행기는 기존 KTCS 루트의 서버 설정과 원문을 읽기만 하며 이를 새로 복제하지 않는다. UI에서 ‘예시 직원으로 인사 기능 시작’을 선택해야 예시 세션/조건을 생성한다. 실제 직원 계정 등록이나 실제 개인정보 입력이 필요하지 않다.

## 이번 작업의 검사 결과

- TypeScript를 포함한 `npm.cmd run build` 통과.
- 새 UI에서 서버 기능·실패 처리 검사 13개와 6개 폭 × 7개 화면의 42개 조합 통과. 13개 중 3개 실패/보류 상태는 응답 가로채기로 검사했으며 실제 서버 장애나 유료 모델 호출로 표현하지 않는다.
- 실제 BFF로 예시 접속, HttpOnly/Strict 쿠키 속성, 추천, 원문 검색·조회, 준비 생성/체크/새로고침 유지, 조건 변경 무효화, 화면 안내 동의, 철회, 접속 종료를 확인했다.
- 질문 요청에 `question` 이외의 프로필 필드를 자동 첨부하지 않으며 브라우저 Authorization 헤더/외부 직접 요청/개인정보용 브라우저 저장소를 사용하지 않는지 확인했다. 쿠키 값·키를 검증 기록에 남기지 않았다.
- 실제 지정 모델 질문 요청 **1건**은 HTTP 200, `needs_review`, 생성 문장 0개·확인된 원문 3개였다. 인용 검사에서 보류된 생성 문장을 숨기고 원문·추가 확인 안내를 PC/모바일에 표시했다. ‘정상 답변 1건’이나 답변 정확도 평가로 집계하지 않는다.
- 실제 모델 응답 상태와 14개 PC/모바일 화면의 간이 텍스트 대비 검사, 총 15개 상태가 통과했다. 전체 접근성 인증·물리적 휴대전화 실검사와는 다르다.
- 기존 8824 시안의 예시 추천, 고정 응답 안내, 서버 API 미호출을 다시 확인했다. 보존한 화면 소스와 병합한 백엔드 소스의 Git 비교도 기록했다.
- 서버의 기존 86개 검사 결과는 원래 채팅의 [백엔드 보고](hr-domain-20261107.md)에 있다. 이번 UI 작업에서 재실행한 것처럼 합산하지 않는다.

검사 함수:

```powershell
npx --yes --package @playwright/cli playwright-cli --session klink-hr-portal open http://127.0.0.1:8825/hr
npx --yes --package @playwright/cli playwright-cli --session klink-hr-portal run-code --filename=scripts/verify_hr_portal.js
# 다음 명령은 기존 설정의 실제 모델을 한 번 요청한다.
npx --yes --package @playwright/cli playwright-cli --session klink-hr-portal run-code --filename=scripts/verify_hr_portal_llm.js
```

결과 JSON과 화면은 [검증·스크린샷](hr-portal-integration-20261107/README.md)에 있다. 기존 [시안 검증 기록](uiux-alternative-20261107/README.md)은 덮어쓰지 않았다.

Codex는 UI·전송 어댑터·실행·브라우저 검사를 담당했다. 앱 코드와 기존 BFF는 조건/권한/출처/버전/인용 경계를 실행한다. 지정 GPT는 일반 질문에 대한 참고 초안 1건을 작성했으며 그 생성 문장은 검사에서 보류됐다. 실제 규정 적용·자격·독립 의미 평가·조직 승인은 별도 확인 대상이다.
