## 화면과 응답 검사

- `source_conditions`를 답변 문단 바로 아래에 표시한다. 원문 항은 접거나 줄 수를 제한하지 않고, 줄바꿈을 보존한다. 회사·문서·조문·사람 승인 전 상태와 전체 출처 열기를 함께 표시한다.
- 이 카드는 **인용한 항의 원문**이다. 필요한 모든 조문을 검색했거나 직원 자격을 확정했다는 뜻이 아님을 카드 위에 안내한다.
- 브라우저에서도 허용된 출처 ID·문서/조문·위치·원문과 발췌의 SHA-256을 비교한다. Python의 유니코드 코드 포인트 위치를 JavaScript의 UTF-16 위치로 오해하지 않도록 `Array.from`으로 대조하고, 해시는 UTF-8로 계산한다. 불일치 응답은 표시하지 않는다.
- `partial_verified_text` 또는 `condition_review_required`가 있으면 `needs_review`를 유지한다. 검증되지 않아 보류된 생성 문장은 표시하지 않는다. 구버전 응답에 조건 카드가 없으면 추가 확인 상태로 안내한다.
- 보존 응답 재생은 ‘보존 응답 재생 · 새 모델 호출 아님’으로 구분한다. 실제 답변과 재생을 같은 호출로 보고하지 않는다.
- 원문 항을 읽기 쉽도록 답변 시작 위치를 대화 영역 안에서 맞춘다. 새 질문 요청은 기존 서버의 두 생성 단계와 토큰 집계 시간을 고려해 기다리며, 실패 시 가짜 답변으로 대체하지 않는다.

## 실제 자료와 연결 전인 부분

현재 참고 원문은 **한국전력 공개 대체자료 10문서·449구간, 사람 승인 0개**다. 실제 KTcs 사내 규정이나 현행성·직원 적용이 확인된 자료가 아니다. 혜택 금액·직원 조건·판정은 예시 규정/가상 직원 체험이다. 공식 회사 양식 0개, 정식 SSO·실제 신청/결재·운영 승인은 연결 또는 확인 전으로 계속 표시한다.

Supabase 적재·스키마 적용·DB 쓰기는 보류했다. `/api/benefits/config`는 외부 직원 저장소를 점검하므로 포털의 자동 조회에서 제외했다. 화면은 ‘적재 보류 · 연결 재검증 미실시’로 표시한다. 이번 변경에서 클라우드 자격증명/연결 상태를 재검사하지 않았다. `.env` 내용·키·JWT를 열거나 복사해 브라우저/기록에 넣지 않았다.

## 이번 UI 검증

이번 결과는 기능·전송·표시 검사이며 검색 성능이나 답변 의미 정확도에 대한 새 평가가 아니다. 결과와 화면은 [검증 자료](hr-condition-ui-20261107/README.md)에 따로 보존한다.

- 기존 기능 검사 **13개**, **6개 폭 × 7화면 = 42개 조합** 통과. 실제 로컬 BFF 경로와 3개의 명시적인 실패/보류 응답 가로채기를 구분했다. 유료 모델 생성 0회. 브라우저 오류·가로 넘침·외부 직접 요청 0개.
- 기존 실제 응답 3개를 재생해 **원문 카드 15개**의 전체 텍스트 일치를 확인했다. 부분 답변 1건의 추가 확인 표시를 포함한다. 잘못된 발췌 해시·위치·전체 조문 확인 주장 차단, 합성 TEST 원문의 유니코드 위치 처리까지 **7개 검사** 통과. 1440/768/390/360px 검사에서 가로 넘침 0개. 새 모델 생성 0회, 클라우드 상태 조회 0회.
- 최신 실제 연결 질문 **1건**은 HTTP 200, `answered`, 답변 1문단·원문 출처 5개·조건 원문 2개였다. 서버가 지정 모델의 초안/원문 대조 **2회 생성**을 보고했고, 전체 출처 재조회도 HTTP 200이었다. KTcs 적용·사람 승인·직원 정보 전송은 모두 false, 클라우드 상태 조회 0회다. PC/모바일에서 확인했다. 이 1건을 원래 채팅의 답변 표본 평가에 합산하지 않는다.
- 앞선 확인 시도 1건은 개발 중 화면 자동 갱신으로 관측이 끊겨 340초 응답 대기 시간초과가 났다. 기록을 보존하고, 안정된 화면을 새로 열어 위 실제 연결을 확인했다. 첫 시도의 제공자 실행/완료 횟수는 확정하지 못했으므로 성공이나 모델 호출 0회로 집계하지 않는다.
- TypeScript를 포함한 프론트 빌드 통과. 빌드된 클라이언트의 키/토큰 형식 리터럴 검사 0건. 백엔드/`supabase` 파일은 `655fd02`와 같고 기존 포털/Workspace/기본 Vite 설정은 `a23dad3`와 동일함을 Git으로 대조했다. 8824 시안·8825 연결 화면·8828 기능 식별 응답은 HTTP 200이었다.

기존 백엔드의 102개 회귀 검사와 답변 표본 대조는 [원래 답변 개선 보고](hr-answer-quality-20261107.md)의 기록이며 이번 UI 작업에서 다시 실행한 것으로 집계하지 않았다. 같은 지정 모델의 원문 재검토는 독립 검증이 아니다. 기존 자동 검토가 조건의 `및`을 `또는`으로 바꾼 오류를 놓쳤고, 543개 대상 중 지정 근거 일부가 상위 5개에 없는 21문항도 남아 있다. 이번 UI 연결로 모든 질문의 조건·예외 완전성, 실제 회사 적용 또는 사람 승인이 완료됐다고 선언하지 않는다.

## 재현

```powershell
python scripts/launch_hr_domain.py --port 8828 --no-open
npm.cmd run dev:hr --prefix web
python scripts/prepare_hr_condition_check.py
npx.cmd --yes --package @playwright/cli playwright-cli --session klink-hr-portal open http://127.0.0.1:8825/hr
npx.cmd --yes --package @playwright/cli playwright-cli --session klink-hr-portal run-code --filename=output/playwright/verify_hr_condition_cards.generated.js
```

재생 준비 스크립트는 기존 로컬 QA 응답을 읽기만 하고 별도 무시된 `output/playwright` 파일을 만든다. 실제 모델 연결 함수 `scripts/verify_hr_portal_llm.js`는 일반 질문 1건으로 서버를 요청하므로 최대 2회의 유료 생성이 발생한다. 기존 기록을 새 실행 결과로 덮어쓰지 않는다.

Codex는 병합·UI·검사·실행을 담당했다. 앱 코드와 기존 BFF는 범위·원문·인용·해시 검사를 실행한다. 지정 GPT는 허용 원문 안에서 답변 초안과 같은 모델의 원문 대조를 수행한다. 실제 규정 적용·독립 의미 검토·조직 최종 승인은 별도다.
