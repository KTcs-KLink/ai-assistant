# 인사 질문 의미 이해 적용 결과 — 2026-11-07

표현이 달라도 같은 업무를 묻는 질문이면 같은 의도로 분석하고, 원질문과 함께 한전 규정을 검색하도록 구현했다. 예를 들어 “월급은 매달 며칠 들어오나요?”와 “회사에서 주는 돈이 통장에 들어오는 날은 언제예요?”는 모두 `regular_payday`로 처리한다. 두 질문의 실제 화면 응답에서 지급일·휴일 예외·인용 원문이 같음을 확인했다.

## 구현과 역할

- **Codex/앱 코드:** 21개 업무 의도 목록, 고용형태·기간·부정·선행조건 보존 검사, 원질문과 분석 결과 연결 검사, 검색 결합 및 화면 표시를 구현했다. 숫자나 조건을 새로 만드는 분석 결과는 거절한다.
- **지정 GPT (`gpt-6-luna`):** 질문을 구조화해 의도와 원문 그대로의 조건을 제안한다. 직원 정보를 추론하거나 규정 사실·답변을 이 단계에서 만들지 않는다. 모호한 질문에는 확인 질문을 한다.
- **검색 모델:** 기존 `BAAI/bge-m3`와 기존 문서 벡터를 사용한다. 원질문과 코드가 만든 의도별 검색어의 결과를 결합한다. 골든셋의 질문·정답·근거 ID는 런타임 검색에 사용하지 않는다.
- **답변:** 원질문과 허용 원문을 바탕으로 생성·대조하고 인용을 검사한다. 일반적으로 의미 분석·초안·원문 대조의 생성 요청이 세 번이다. 정기 급여 지급일은 좁은 원문 추출 경로로 실제 조문의 날짜와 예외를 읽어 설명하므로 의미 분석 한 번만 필요하다. 토큰 집계 요청은 별도다.

고용형태, 업무상/일반 사유, 기간, 선행조건이 다르면 같은 답으로 합치지 않는다. “급여 계산기간”과 “급여 지급일”도 다른 업무로 처리한다. 분석 실패 시 확인 필요로 멈추며, 원질문을 버리거나 이전 방식으로 조용히 우회하지 않는다.

분석은 서버의 기존 설정으로만 실행한다. 구조화된 응답은 형식 제약이며 내용의 정답을 보증하지 않는다. 구현 참고: [OpenAI Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs).

## 실제 답변·화면 검사와 남은 한계

- 첫 구현 실제 응답 23개: `answered` 15개, `needs_review` 8개. 설명 범위 수정 후 6개 재실행: 5개와 1개. 마지막 수정 후 지급일 2개·조건 비교 3개: 4개와 1개. 반복 실행은 별도 보존했으며 서로 독립인 34문항 성능으로 합산하지 않는다. 상태 값은 코드 결과이며 의미 정확도 채점이 아니다.
- 최종 화면에서 지급일 두 표현의 답변 본문과 인용 근거가 동일했다. “정기 급여 지급일로 이해했어요” 표시, 직접 인용 일치, 모델 생성 호출 1회, 모바일 가로 넘침 없음, 브라우저 오류 없음, 직원 프로필 전송 없음, 외부 브라우저 요청 없음을 확인했다.
- 계약직 업무상 부상과 정규직 업무상 부상의 적용 원문을 구분했다. 일반 육아휴직과 출산휴가에 이은 육아휴직의 조건도 보존했다. **일반 육아휴직 3개월의 결원 보충 질문 한 건은 조건 설명 검사에서 답변이 보류됐다.** 완전 답변 성공으로 세지 않는다. 계약직 병가 응답 역시 적용 대상 확인이 남아 있다.
- 한 번에 너무 많은 검사 프로세스를 실행해 OpenBLAS 메모리 오류가 발생했다. 실패 결과는 `after-v3/resource-failure.json`에 별도 보존·제외했다. 계산을 작은 벡터 연산으로 바꾸고 실행 스레드를 제한한 뒤 검색 재검사, 실제 답변, 화면 검사를 통과했다.
