# KLINK 글로벌 벤치마킹과 자동화 화면 구성

조사 기준일: 2026-11-09. 공개된 공식 제품 자료와 문서 18개 서비스를 비교했다. 목표는 복지 추천을 제외한 직원용 인사 AI와 고객사 관리자 SaaS에 추가할 자동화, 그 기능을 사용할 화면, 승인과 실행 이력을 함께 정하는 것이다. 회사별 유료 콘솔에 로그인해 사용한 비교나 성능 순위는 아니다.

**직원은 질문·원문·내 할 일을 한 곳에서 확인하고, 관리자는 문의·자료·승인을 처리하며, 자동화는 한 곳에서 정의하고 실행 이력을 추적하는 구조를 제안한다.** 화면 스타일은 현재 페이퍼·스톤 디자인을 유지하고, 업무 메뉴와 처리 흐름을 확장한다. 아래 업체 기능과 KLINK에 적용할 설계는 구분한다.

## 우선 적용할 화면 구조

### 직원 업무 공간

왼쪽 메뉴는 업무 홈 / AI 도우미 / 규정·양식 / 내 할 일 / 내 문의로 구성한다. 계정은 메뉴 하단, 알림은 상단에 둔다. ‘내 할 일’에는 요청받은 규정 확인·서류 보완·권한이 있는 승인만 보여준다. 직원에게 수집·청크·토큰 같은 운영 항목을 기본 노출하지 않는다.

| 위치 | 배치할 내용 | 연결되는 동작 |
| --- | --- | --- |
| 홈 상단 | 현재 접속·회사 적용 상태, 빠른 질문 | 실제 질문 작성창으로 이동 |
| 홈 중앙 | 내가 처리할 일과 처리 안내 | 보완 제출·확인 요청·권한이 있는 승인 |
| 홈 하단 | 최근 문의와 자주 찾는 원문 | 문의 상세·규정 원문 |
| AI 답변 옆 | 인용 원문·회사·시행일·검토 상태 | 원문 확인, 필요한 양식, 문의로 전환 |
| 내 문의 상세 | 접수→배정→추가 확인→해결 타임라인 | 내용 보완, 처리 안내 확인, 재문의 |

### 고객사 관리자

기존 여덟 화면을 다음 여덟 개의 상위 메뉴로 확장한다. 하위 목록과 탭으로 역할을 묶고 화면마다 같은 지표와 승인함을 중복 생성하지 않는다.

| 상위 메뉴 | 하위 화면 또는 탭 | 기본 화면의 중심 |
| --- | --- | --- |
| 운영 현황 | 오늘 할 일 / 장애·지연 / 최근 실행 | 관리자가 지금 처리할 일 |
| 인사 서비스 | 문의 큐 / 통합 승인함 | 담당자·기한·다음 행동 |
| 지식 자료 | 자료 연결 / 문서 / 원문·청크 / 검토·승인 / 검색 시험 | 자료 상태와 답변 사용 범위 |
| 자동화 센터 | 규칙 / 실행 이력 / 템플릿 | 어떤 조건에서 무엇이 실행되는지 |
| AI 품질 | 사용자 신고 / 검토 큐 / 질문 세트 / 변경 비교 | 어떤 답변을 왜 검토할지 |
| 사용량·비용 | 토큰·추정액 / 부서·기능별 / 예산 / 청구 대조 | 비용 발생 원인과 대응 |
| 회사 설정 | 조직·직원·권한 / 연동 / 알림 / 디자인 | 회사별 운영 범위 |
| 변경 이력 | 접속·자료·권한·승인·설정 | 누가·언제·무엇을 변경했는지 |

자동화 화면의 ‘승인 대기’ 링크는 통합 승인함의 해당 유형 필터로 이동한다. 승인 요청·이력은 같은 기록을 사용한다. 자료 처리 작업과 인사 업무 자동화는 실행 유형·권한을 구분한다.

### 서비스 운영자

고객사 관리자와 진입·권한을 분리해 고객사 / 요금제·청구 / 서비스 상태 / 작업·장애 / 배포·변경 / 지원 접근을 둔다. 회사별 운영 메타데이터가 기본이며 원문 전체 열람과 지원 대행은 별도 범위·사유·기간·승인 이력으로 관리한다.

## 자동화 센터 상세 배치

기본은 템플릿을 고른 뒤 시작 조건·대상·동작·승인·실패 대응을 채우는 방식이다. 첫 화면부터 자유로운 대형 캔버스를 요구하지 않는다. 분기와 연결이 복잡해질 때 단계 보기로 확장한다.

| 영역 | 규칙 편집 | 실행 이력 | 승인 요청 |
| --- | --- | --- | --- |
| 상단 | 규칙 이름·상태·버전·담당자, 시험 실행 | 실행 ID·시각·대상·현재 단계 | 요청 목적·요청자·유효기간·대상 범위 |
| 왼쪽 | 시작 조건과 단계 목록 | 실행별 목록, 성공·실패·대기 필터 | 승인 요청 목록과 기한 |
| 중앙 | 조건→동작→검토 단계, 입력값 확인 | 단계별 시작/종료·오류·결과 | 이전/새 버전·실제 변경 값·근거 비교 |
| 오른쪽 | 회사·권한·자료 범위·예산·재시도 | 해당 단계의 결과·재시도·원문 위치 | 승인/보완 요청/거절·설명·다음 승인자 |
| 하단 | 시험 결과, 저장·활성화 | 실행 이력·영향 범위·보고서 | 변경 이력·실행 결과·복구 대상 |

상태는 초안 / 시험 중 / 검토 대기 / 활성 / 일시정지 / 오류로 구분한다. 규칙 버전과 실행 ID는 별개로 보존한다. 시험 실행은 선택 자료의 별도 버전에서 수행하고, 새로운 모델 호출·임베딩이 필요한 단계는 예상 범위·사용량을 먼저 표시한다.

| A05 | 해결되지 않은 AI 질문 | 질문·선택 답변·출처로 문의 초안 작성, 공유 항목 표시 | 직원의 문의 등록과 전달 내용 | 답변 하단→문의 작성 |
| A06 | 문의 분류·배정: 일반 문의 접수 | 업무 분류 후보→권한 있는 담당자 배정→기한 추적 | 민감·예외 문의, 담당자/우선순위 변경 | 문의 큐 / 담당자 할 일 |
| A07 | 공식 양식 작성 보조: 직원이 업무 선택 | 승인된 양식·필수 항목 안내·파일 형식 검사·초안 | 직원의 내용 확인·실제 제출·회사 결재 | 규정·양식→작성 / 통합 승인함 |
| A08 | 반복 질문 정리: 누적된 허용 기록 | 비슷한 질문 묶음·FAQ 후보·인용 근거 제안 | 내용·표현·회사 적용·공개 승인 | AI 품질→지식 개선 후보 |
| A09 | 비용·지연 이상 감지: 정한 임계치 | 실제 사용량·예산 예약·알림·새 요청 제한 정책 | 한도 변경·예외·사용 재개 | 사용량·비용 / 운영 현황 |
| A10 | 검색·답변 회귀 검사: 새 규정·설정 버전 | 승인된 질문 세트로 검색·인용 검사·비용/지연 비교 | 답변 의미·예외·회사 반영 승인 | AI 품질→변경 비교 / 반영 요청 |
| A11 | 조직 변경 반영: 승인된 HRIS/SSO 이벤트 | 직원·부서 변경 반영·기존 세션/권한 회수·이력 | 관리자 권한 확대·예외 접근 | 회사 설정→직원·권한 |
| A12 | 운영 백업·복구 점검: 지정 주기·배포 | 원본·운영 기록·설정·색인 버전 백업, 복구 시험·실패 알림 | 운영 버전 복원·복구 범위 | 서비스 상태 / 변경·배포 이력 |

자동 알림은 승인된 채널·대상·빈도로 설정한다. AI 질문이나 문의 전체를 외부 채널로 기본 전송하지 않는다. FAQ 후보·자동 검사 결과·담당자 배정은 조직의 최종 규정 승인이나 고용 판단을 대신하지 않는다.

## 현재 기능에서 확장되는 범위

| 영역 | 현재 확인한 구현 | 추가할 연결 |
| --- | --- | --- |
| 수집 | 선택한 등록 파일 재다운로드·해시 확인 | 주기 실행·변경 감지·검토 할 일 |
| 재적재 | 기존 검증 청크로 별도 FTS5 생성 | 새 자료 파싱·청크 검토·선택 임베딩·검색 시험·승인 반영·복구 |
| 검토 | 사유·상태 메모 저장 | 실제 승인선·담당자·유효기간·승인된 범위 활성화 |
| 문의 | 세션별 등록·상태·안내 | 실제 직원 연결·배정·기한·추가 확인·알림 |
| AI | 실제 검색·답변·인용 원문 | 신고·검토 큐·시험 질문·변경 비교·문의 전환 |

새 문서를 받았다고 바로 답변 범위에 넣지 않는다. 검토 전용 발췌·개인정보 제외·회사 적용 미확인 상태를 유지하며 원본과 기존 색인은 보존한다. Supabase 적재는 보류한다.

## OpenSearch를 어디까지 참고할지

OpenSearch는 이 조사에서 인사 SaaS가 아니라 **검색·색인 운영 도구**의 비교 대상이다. ISM의 상태·조건·동작 편집, Dashboards의 관리 흐름과 모니터의 실행·오류·알림 상태가 참고 대상이다. 이것만으로 회사 SSO, 인사 승인, 실제 청크의 조직 승인, LLM 토큰 비용 관리가 연결되지는 않는다.

현재 BGE·단어 결합 검색을 즉시 교체하지 않는다. 도입을 비교한다면 별도 실험에서 같은 승인 자료·질문·권한 조건으로 검색 성능, 한국어 조문 검색, 지연·운영비, 자료/회사 분리, 버전 활성화·복구를 측정한다. 검색 성능과 최종 LLM 답변 평가는 분리한다. 인프라를 추가하는 비용까지 확인한 뒤 선택한다.

## 개발 순서

1. 통합 할 일·승인함과 문서/문의 담당자를 먼저 연결한다. 회사·직원·자료 권한이 없는 단계는 로컬 설계·시험 상태로 표시한다.
2. A01 변경 감지와 A03 실패 재처리를 기존 수집·작업에 추가하고, A02 문서 처리의 시험·검토 화면을 연결한다.
3. A05 문의 전환과 A06 배정을 붙여 직원 질문에서 담당자 처리까지 한 흐름으로 확인한다.
4. A09 비용 이상과 A10 품질 검사를 연결하고, 승인된 범위에서 A07·A11의 실제 회사 시스템 연동으로 확장한다.

현재 화면의 시각 조절은 [디자인 스튜디오](http://127.0.0.1:8825/hr/design), 기존 14개 화면은 [와이어프레임](http://127.0.0.1:8825/hr/wireframes)에서 볼 수 있다. 추가 기능 전체 목록은 [SaaS 기능 우선순위](hr-saas-feature-backlog-20261109.md)에 별도로 정리했다. 이 문서의 새 자동화·승인 화면은 적용 설계이며 현재 동작하는 기능으로 표시하지 않는다.
