# K:LINK 최종 UI/UX 구현 시안

기준일: 2026-11-07. 작업 브랜치: `feat/final-uiux-20261107`. 사용자 요청에 따라 백엔드 연결보다 전체 화면과 사용 흐름을 먼저 완성했다. PR은 만들지 않는다.

## 바로 체험하기

Windows에서 저장소의 `start_uiux.cmd`를 더블클릭한다. 또는 `python scripts/launch_uiux_preview.py`를 실행한다. 최초 설치는 `npm ci --prefix web`, 변경 후 빌드 갱신은 `python scripts/launch_uiux_preview.py --rebuild`이다.

전용 주소는 `http://127.0.0.1:8822/workspace`다. 실행기는 프론트엔드만 열며 API 서버·GPT·Supabase·로컬 인사 원문을 시작하거나 읽지 않는다. 다른 서비스가 포트를 사용 중이면 멈추며, 해당 프로세스를 종료하지 않는다. 기존 `/benefits`, 로그인, 대화, 관리자 경로와 기존 실행기는 보존했다.

공통 메뉴는 PC 왼쪽 5개 메뉴, 모바일 아래 5개 메뉴와 전체 메뉴다. 통합 검색은 상단과 Ctrl/Cmd+K로 열고 검색 결과는 자료실로 연결한다. 알림은 화면 검토용 예시다. 상세창은 native dialog로 초점을 가두고 Esc로 닫는다. 상태 탭은 방향키·Home·End를 지원한다.

색상은 숲색의 주요 동작, 연한 세이지 배경, 흰 정보 카드, AI의 옅은 보라색으로 구성했다. 색과 함께 상태 문구·아이콘을 표시한다. 한글 설명의 글자 크기와 명도를 보정했고, 모바일 입력 글씨는 16px을 사용한다. 글꼴은 Pretendard v1.3.9를 로컬 제공하여 외부 폰트 요청을 제거했다. 배포 라이선스는 `web/public/fonts/OFL-Pretendard.txt`에 포함했다.

## 벤치마킹을 반영한 판단

공개 화면과 공식 문서의 확인 범위는 [벤치마킹 기록](benefits-benchmark-20261107.md)을 따른다. 로그인 뒤의 실제 개인 추천 화면을 직접 확인했다고 주장하지 않는다.

- 복지로: 제공한 조건에서 출발해 받을 가능성이 있는 혜택을 찾는 구조를 회사 혜택 탐색에 적용했다. 공공 복지 자격 기준을 회사 규정으로 전용하지 않았다.
- 정부24 혜택알리미: 나의 혜택·관심·설정 흐름을 혜택 목록·저장·동의 관리로 정리했다.
- 웰로: 공개 정책 탐색과 맞춤 추천의 구분을 참고했다. 뉴스·광고성 피드는 사내 업무 화면에 추가하지 않았다.
- 토스: 현재 공식 UI/UX 가이드의 다음 행동을 알 수 있는 버튼, 쉬운 해요체, 진입 흐름을 가로막지 않는 경험을 참고했다. 앱인토스 입점 전용 레이아웃 규칙이나 토스 자산을 복제하지 않았다.

## 실제 연결과의 경계

이 경로는 **최종 화면 구성을 검토하는 작동 시안**이다. 회사 운영 서비스의 완료나 디자인에 대한 사용자 최종 승인을 뜻하지 않는다.

- 직원은 체험 직원 한 명이다. 이름·사번·실제 생년월일을 받지 않는다. 2026-11-07 고정 예시 기준일로 근속·나이·마감을 비교한다.
- 규정·혜택 금액·기간·임계값은 모두 가상이다. 클라이언트의 예시 조건 비교이며 실제 KTcs 자격 검증이 아니다. 불명확한 필수 조건은 추가 확인으로 남긴다.
- AI는 고정 예시 응답이다. 외부 모델 호출·RAG 검색·성능 평가를 수행하지 않는다. 근거 본문과 출처 ID도 가상이며 확인하지 않은 해시를 만들어 붙이지 않았다.
- 회사 공식 양식은 연결 전이다. 휴가신청서·출장신청/사전품의서·출장비 정산서·사직원·업무인수인계서·퇴직업무 확인서의 유형과 준비 항목만 보여준다. 생성 파일을 공식 양식으로 제공하지 않는다.
- 준비 항목 확인은 증빙 검증이나 지급·휴가 승인과 다르다. 실제 제출 버튼은 비활성 상태이며 제출되지 않는 이유를 함께 보여준다.
- 조건·대화·저장 상태는 현재 탭 메모리에서만 유지한다. localStorage·서버·Supabase에 저장하지 않는다. 새로고침하면 예시 초기 상태로 돌아간다.
- 정식 로그인·승인된 HR 연결·Supabase 본인 저장·RLS·KTcs 승인 규정·실제 RAG·공식 양식/결재·실제 알림은 후속 연결 사항이다.

수행 명령:

```powershell
npm run build --prefix web
server\.venv\Scripts\python.exe -m pytest server/tests scripts/tests -q
python scripts/launch_uiux_preview.py --no-open
npx --yes --package @playwright/cli playwright-cli -s=klink-final-ui open http://127.0.0.1:8822/workspace
npx --yes --package @playwright/cli playwright-cli -s=klink-final-ui run-code --filename=scripts/verify_uiux_desktop.js
npx --yes --package @playwright/cli playwright-cli -s=klink-final-ui run-code --filename=scripts/verify_uiux_responsive.js
```

캡처는 로컬 `output/playwright/final-uiux-*.png`, 구조화된 결과는 KTCS 작업 폴더의 `outputs/klink_final_uiux_20261107/desktop.json`과 `responsive.json`에 보관한다. 모두 가상 데이터만 사용했다. 자동 UI 검사를 사용자 사용성 평가·전체 접근성 인증·검색 성능 평가·답변 의미 보증으로 표현하지 않는다.

Codex는 UI 구현·브라우저 조작·검증을 수행했고, 앱 코드는 예시 조건 비교와 메모리 상태·화면 이동을 담당한다. 이번 UI 작업에서 GPT API 호출은 0건이다.
