# KLINK SaaS 추가 기능과 개발 우선순위

기준일: 2026-11-09. 복지 추천·개인별 복지 조건은 제외한다. 현재 원문 기반 AI 답변과 로컬 운영 기능을 토대로 실제 고객사가 사용할 SaaS로 확장하는 기능 목록이다. 아래 추가 항목은 개발 계획이며 구현 완료와 구분한다.

먼저 **회사별 자료·계정 분리 → 정식 인증과 문서 권한 → 문서 처리·검토·검색 반영 → 답변 품질 관리**를 연결한다. 이후 직원 업무와 관리자 비용·운영을 고도화하고, 유료 고객 운영 기능을 추가한다. Supabase 적재는 기존 보류 상태를 유지한다. 이 목록만으로 새 DB 구축·대규모 재임베딩·배포를 시작하지 않는다.

## 현재 구현과 역할

현재 직원 화면에는 업무 홈, 실제 원문 검색·AI 답변·인용 확인, 규정·양식 안내, 로컬 문의 등록·결과 확인, 접속 정보가 있다. 관리자에게는 원문 목록, 선택 파일 재수집·무결성 검사·별도 FTS5 스테이징, 검토 메모, 실제 응답 토큰·단가 기반 추정 비용, 예산 정책, 문의 처리, 변경 이력이 있다. 현재 인증은 로컬 체험이며 검토 메모 저장이 회사 승인이나 답변 범위 승격으로 이어지지 않는다.

실제 SaaS에서는 다음 세 역할을 구분한다.

| 역할 | 주요 업무 | 접근 범위 |
| --- | --- | --- |
| 직원 | 질문·원문 확인·일반 문의·처리 결과·공식 양식 | 본인 정보와 조직이 허용한 문서 |
| 고객사 관리자 | 직원·부서·문서·검토·문의·예산·운영 정책 | 소속 고객사 범위 |
| 서비스 운영자 | 고객사 개설·요금제·서비스 상태·장애·배포 | 운영에 필요한 정보. 고객사 원문 전체를 기본 열람하는 권한과 분리 |

## 메뉴 구성 제안

직원은 업무 홈 / AI 도우미 / 규정·양식 / 내 문의 / 알림 / 내 계정을 사용한다. 대화 기록은 AI 도우미 안에 둔다.

고객사 관리자는 운영 현황 / 자료·문서 / 수집·처리 작업 / 검토·승인 / AI 품질 / 직원 문의 / 사용량·비용 / 직원·권한 / 회사 설정 / 변경 이력을 사용한다. 현재 여덟 화면은 이 구조로 확장하고 중복된 통계는 새 메뉴마다 만들지 않는다.

서비스 운영자는 고객사 / 요금제·청구 / 서비스 상태 / 장애·작업 / 배포·변경 이력 / 지원 접근을 사용한다. 고객사 관리자 화면과 진입·권한을 분리한다.

## 바로 다음 개발 묶음

1. 로그인·회사 구분·직원/문서 권한과 회사 적용 상태를 먼저 연결한다.
2. 문서 업로드→청크 확인→임베딩→검토→시험 검색→승인 반영→복구를 한 문서 기준으로 연결한다.
3. 답변 평가·오류 신고·문의 전환과 담당자 배정까지 실제 질문으로 확인한다.
4. 사용량 배부·동시 예산 제한·장애/작업 알림을 연결한 뒤 도입·요금제 기능을 붙인다.

앱 코드는 권한·검색 범위·출처/버전/해시·토큰 한도·비용·인용 검사를 강제한다. GPT는 허용된 근거 안에서 의미 판단·답변 초안을 맡는다. 회사 규정의 최종 적용·현행성·운영 승인은 별도로 확인한다.
