## 데이터와 실행 경계

- 기존 `workspace/catalog.ts`, `forms.ts`, `model.ts`, `WorkspaceContext.tsx`의 가상 자료·판정 로직·메모리 상태를 재사용했다. 회사 자료나 원본 데이터는 바꾸지 않았다.
- 초기 가상 조건은 정규직·2019-03-11 입사·만 5/9세 자녀·가구원 4명이다. 초기 화면의 두 동의도 **가상 시나리오**이며 실제 사용자 동의 이력이 아니다.
- 현재 추천 수는 가상 규정 6건의 조건 결과다. 실제 KTcs 자격·수급 가능성·잔여 휴가·인사 이력을 확인하지 않는다. 가족 돌봄 휴가는 예시 일수만 표시하며 유급 여부 등은 확인 대상으로 남는다.
- AI 화면은 정해진 문구와 로컬 규칙으로만 응답한다. GPT 호출, RAG, 검색 성능 평가, 답변 의미 평가를 수행하지 않았다.
- 공식 양식을 생성·다운로드·제출하지 않는다. 안내하는 것은 양식 종류와 준비 항목이다.
- 상태는 메모리에만 존재한다. 새로고침하면 초기 가상 조건으로 돌아간다. 동의 철회는 조건·대화·준비 정보를 비운다. 저장한 혜택 ID는 개인정보 없는 북마크로 남는다.
- SSO·Supabase·BFF·신청 시스템은 미연결이다. 실제 자격 확인·신청·승인·알림 발송이 일어나지 않는다.
- `.env`는 열거나 복사하지 않았다. 실제 직원·회사 규정·API key를 넣지 않았다. 새로운 UI에서 외부 요청·백엔드 호출이 없는지 브라우저에서 검사한다.
- 원래 `klink-demo-ui` 체크아웃, 8822 포트, 백엔드와 `supabase/migrations`는 수정하지 않는다. PR을 만들지 않는다.

## 인사 기능 연결을 위한 화면·동작 계약

이 절은 **후속 연결 요구사항**이며 현재 구현된 통신 계약이 아니다. 원래 채팅에서 전달한 BFF 경로 목록을 기준으로 작성했다. HTTP 메서드, 요청/응답 필드와 오류 코드는 원래 브랜치의 `docs/hr-domain-20261107.md` 및 실제 서버 구현과 먼저 대조해야 한다. 다른 채팅의 미완성 코드를 이 clone으로 복사하거나 임의로 수정하지 않는다.

| 화면 동작 | 전달받은 BFF 경로 | 화면에서 필요한 정보·제약 |
| --- | --- | --- |
| 홈·자료 탐색의 인사 업무 목록 | `/api/benefits/hr/catalog` | 실제 허용 업무 ID, 분류, 표시명, 안내 범위. 목록에 존재한다는 이유로 개인의 수급 자격을 확정하지 않음 |
| 조건·근거 보기 | `/api/benefits/hr/evidence`, `/api/benefits/hr/sources/:id` | 허용 출처 ID, 회사, 적용 범위, 버전·시행일, 원본 해시, 원문 위치, 검토 상태, 인용문. 가상 자료와 실제 자료의 모드를 명확히 구분 |

사용자 조건/동의와 개인별 자격 결과의 실제 소유 API는 인사 계약 문서에서 추가 확인해야 한다. 위 `catalog` 경로에 자격 계산을 임의로 가정하지 않는다. 새 UI는 조건별 이유를 보여줄 수 있지만, 서버가 검증한 회사·범위·시점·동의 상태와 필요한 조건/예외를 모두 받기 전에는 실제 자격 확인 완료로 표시하지 않는다.

연결 담당자가 지켜야 할 경계:

1. 기존 HttpOnly 세션을 사용한다. 브라우저에 Supabase/GPT key를 전달하거나 `.env`를 프론트 빌드에 넣지 않는다. 세션·권한·CSRF·소유권 검사는 서버 책임이며 이 데모에서는 검증하지 않았다.
2. 데모와 실연결 모드는 명시적으로 분리한다. 연결 실패 시 가상 규정을 실제 회사 답변처럼 대신 표시하지 않는다.
3. 개인 추천에는 동의한 최소 조건만 전송한다. 실제 서비스에서는 철회 완료 응답을 확인한 후 관련 개인 캐시·대화·준비 데이터를 정리한다. 현재 메모리 초기화를 서버 삭제 완료로 해석하지 않는다.
4. 서버가 허용 출처·회사·버전·범위·해시·검토 상태를 확인한다. 인용 ID·직접 인용·수치는 원문과 대조한다. 기계 검사와 조직의 최종 승인은 구분한다.
5. 필요한 조건·예외를 잘라 답변하지 않는다. 근거 묶음이 모델 요청 한도를 넘거나 핵심 의존관계가 미확인이면 검토 필요 상태를 표시한다. 생성 모델 토큰 한도는 서버에서 집계한다.
6. 실제 양식 URL은 허용된 공식 출처와 사용자 접근 권한을 확인한다. 양식 없음/접근 불가/버전 불명 상태는 다운로드 버튼 대신 이유를 표시한다.
7. 출처 버전·입력 조건이 바뀌면 체크와 판단을 재확인한다. ‘준비 완료’가 ‘신청 완료’나 ‘승인 완료’를 뜻하지 않는다.

오류 화면 계약도 실제 서버와 함께 확정해야 한다. 세션 만료는 개인 정보 숨김과 재로그인, 권한 없음은 접근 불가, 버전 충돌은 근거 재조회, 한도 초과는 근거 검토 필요, 제한 응답은 재시도 안내로 연결한다. DB/근거가 준비되지 않으면 ‘서비스 확인 필요’로 표시한다. **이 오류 화면들은 후속 연결 요구사항이며, 실제 API 실패 경로를 시험했다고 보고하지 않는다.**

## 실행·검사·변경 파일

같은 PC에서 [새 시안](http://127.0.0.1:8824/workspace)을 연다. `start_ui_alternative.cmd` 또는 `web` 폴더에서 `npm.cmd run dev:alternative`로 시작한다. 다른 서비스가 8824를 쓰면 `--strictPort`로 실패하며 다른 포트를 자동 점유하지 않는다. 실제 휴대전화 접속 검증과 외부 배포는 수행하지 않는다.

- 구현: `web/src/portal/{PortalApp,Dashboard,Pages,Assistant,ui}.tsx`, `portal.css`.
- 진입점: `web/src/App.tsx`의 `/workspace` 지연 로딩 대상만 변경했다. 기존 `workspace` 소스는 보존했다.
- 표시·실행: `web/index.html`, `web/public/favicon.svg`, `web/package.json`, `start_ui_alternative.cmd`.
- 재현 검사: `scripts/verify_alternative_ui.js`는 Playwright CLI의 `run-code --filename`으로 실행한다. 프론트 8824만 검사한다.
- 결과·스크린샷: `docs/uiux-alternative-20261107/`에 최종 화면과 검증 JSON을 별도로 보관한다. 상세 실행 산출물은 로컬 `output/playwright/`에 있다.

최종 `npm.cmd run build`(TypeScript 포함)가 통과했다. 브라우저 동작 12개, 6개 화면 폭 × 7개 화면의 42개 조합이 통과했고, 검사 중 브라우저 오류·외부 HTTP 요청·백엔드 API 호출은 0건이었다. PC/모바일 14개 페이지의 간이 텍스트 대비 검사도 통과했다. 전체 접근성 인증을 뜻하지 않는다. 빠른 탭 전환 직후 검색할 때 앞선 필터가 사라지는 문제를 현재 URL 병합으로 수정했다. 최종 기록과 화면은 [검증·스크린샷](uiux-alternative-20261107/README.md)에 있다. 범위는 화면·기능 동선·반응형 검사다. 검색 성능, 답변 의미, 회사 규정 승인, 실세션·DB·SSO·신청 연결 검증과 구분한다.

Codex가 공식 자료 조사·구현·실행·브라우저 검사를 담당했다. 앱 코드는 기존 가상 조건 판정과 메모리 상태를 사용한다. 이 작업에서는 `.env`의 GPT 모델을 호출하지 않았다.
