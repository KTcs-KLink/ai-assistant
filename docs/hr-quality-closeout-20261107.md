# 한전 인사 답변 21+1문항 수정과 재검증

이번 작업은 한전 공개 인사 원문으로 검색 누락 21문항과 설명이 부족했던 1문항을 실제로 다시 생성해 대조하는 작업이다. Supabase 적재, 실제 직원 자격 확정, KTcs 사규 적용은 수행하지 않았다. PR도 생성하지 않았다.

## 달라진 동작

- 단어 검색에 기존 `BAAI/bge-m3` 문서 벡터를 연결했다. 원래 8,511개 배열에서 현재 허용된 449개 조문에 대응하는 456개 벡터만 사용한다. 새 질문은 한전 전용 로컬 검색 모델에서 계산한다. 골든 질문 ID나 정답을 서비스 검색에 넣지 않는다.
- 개정일의 닫는 `>` 기호를 제목 경계로 잘못 처리하던 문제를 고쳤다. 복수 업무 질문의 각 주제와 같은 버전의 조문 참조를 검색에 반영했다.
- GPT는 원문 구간 번호를 선택하고 프로그램이 해당 원문을 그대로 인용한다. 모델이 인용문의 기호·표현을 다시 쓰는 경로를 없앴다. 허용되지 않은 ID, 수치, 다른 프로젝트·모델의 검색 연결은 차단한다.
- 일반 휴직 기간과 더 짧은 예외가 함께 있는 규정에서 일반 요건을 빠뜨린 답변을 차단한다. 외출의 허용 목적을 임의로 넓히거나, 근거 없는 직급 상하관계로 예외 포함·제외를 확정하는 답변도 보류한다. 이 검사는 발견한 오류에 대한 제한된 검사이며 전체 의미 정확성 보증이 아니다.

Codex와 앱 코드는 자료 범위·검색·원문 복원·수치·출처·한도 검사와 테스트를 담당했다. 기존 `.env`의 동일 설정 GPT는 실제 답변 생성과 보조 의미 대조에 사용했다. 매 질문마다 Codex가 호출되는 구조는 아니다.

## 완료라고 확정하지 않은 부분

- `01-037`: 공개채용의 가족 우대 금지와 특별채용 조문의 채용권자 금지는 구분했지만, 후자의 공개채용 적용 범위는 원문만으로 승인하지 않았다.
- `03-041`: ‘2직급 이하’ 예외에 다른 직급이 포함되는지 판단할 조직 직급 체계의 허용 근거가 없다. 포함·제외를 단정한 생성문을 차단하고 검토할 원문을 제공한다. 이 문항은 답변 완료로 세지 않는다.
- 동일 설정 GPT의 자동 판정은 독립적인 사람 승인과 다르다. 사망자 유족을 묻는 질문에 생존자 청구권까지 요구하거나, 질문에 필요한 육아휴직 설명이 있는데 다른 일반 휴직까지 요구한 판정도 있었다. 원시 판정은 삭제하거나 통과로 덮어쓰지 않았다.
- 최종 선택 답변의 자동 판정은 완전 18, 불완전 2, 부정확 1, 보류 1이다. 이 수치는 여러 수정 단계에서 선택한 실제 응답의 기록이며 단일 새 실험의 정확도나 서비스 전체 정확도가 아니다. 543문항·960문항 전체의 최종 답변 의미 평가를 새로 실행한 것은 아니다.
- 한전 원문의 현행성, KTcs 적용, 사람의 독립 의미 승인, 실제 직원 인증·권한·신청·결재는 미확인이다. Supabase 적재 및 실사용 준비 상태는 계속 `HOLD`다.

## 로컬 증거

KTCS 작업 폴더의 `outputs/klink_hr_quality_closeout_20261107/`에 다음을 보존했다.

- `comparison.html`: 22문항의 실제 수정 전후 답변과 대조 원문.
- `final/case-audit.json`, `final/summary.json`: 선택한 실제 생성 단계, 원시 자동 판정, 코드 재검사 및 보류 사유.
- `data-inventory.json`: 골든 960문항, 원문 3,870개와 임베딩 8,511개, 현재 449개 조문 범위의 실제 확인.
- `baseline/`, `after/`, `after-v2/`부터 `after-v6/`: 실패·보류·수정 응답을 포함한 모든 단계. 원본·골든셋·기존 벡터는 보존.

재현 도구는 `scripts/closeout_hr_quality.py`, `probe_hr_embedding_reuse.py`, `verify_hr_quality_sources.py`, `report_hr_closeout.py`다. 생성과 의미 대조는 설정된 GPT API를 사용하지만 자료·검색·검증 산출물은 로컬에 보존하며 직원 프로필을 전송하지 않는다.
